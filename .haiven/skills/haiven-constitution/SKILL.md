# Haiven Constitution Skill

Use this skill for any implementation task in `heard`.

## 1) Classify the change first

Pick one or more:

- `domain logic`
- `API contract`
- `workflow`
- `eventing`
- `auth/permissions`
- `tenant isolation`
- `provider integration`
- `UI/UX`

## 2) Build test-first, not test-later

Tests are required and should be planned before code.

Minimum expected coverage depends on change scope:

- Unit tests for deterministic logic and validation.
- Integration tests for service, database, provider, and workflow behavior.
- Contract tests when API/event contracts change.
- Permission and tenant-isolation tests for protected behavior.
- Failure-mode tests for critical workflows.

## 3) Use BDD for critical workflows

When a workflow is multi-step, permission-sensitive, user-facing, provider-backed, or event-driven, include scenario-style tests:

- Given known system state
- When user or system action occurs
- Then business outcome is correct
- And permissions, audit visibility, and event behavior are enforced

Do not force heavyweight BDD for small deterministic utilities.

## 4) Respect shared-service boundaries

- Use Passage for shared identity/session/account behavior.
- Use qurl for QR generation and rendering.
- Temporary local adapters are only for documented fake/test/offline use.

## 5) Protect environment files

- Keep actual environment files out of Git with `.env`, `.env.*`, and `!.env.example` in `.gitignore`.
- Commit only sanitized placeholders in `.env.example`.
- If an actual environment file was tracked, remove it from Git tracking and rotate any exposed credentials.

## 6) Keep browser identity origins canonical

- Configure one canonical public browser origin per environment, including local, integration, staging, and production.
- Redirect aliases before issuing OAuth, session, CSRF, PKCE, or state cookies.
- Derive or validate OAuth callbacks, CORS, and branded return URLs against that configured origin; never use an untrusted request host to select a callback.
- Require HTTPS and explicit configuration outside local runtimes, and add regression tests for origin/callback drift.

## 7) Done means done

Before completion, verify all applicable items:

- Contracts updated first when behavior changes.
- Tests added and passing.
- Permissions and tenant boundaries enforced.
- Failure handling and observability included.
- Docs updated for durable decisions.
- Supply-chain policy, dependency audit, immutable CI action, least-privilege credential, SBOM, and provenance checks pass.
